# Задания для экспертов

## Цель

Проверять, как харнесс извлекает экспериментальные данные из научных источников, находить и воспроизводимо описывать ошибки, а затем готовить только обезличенные и проверенные калибровочные данные для внешнего датасета.

## Состав группы

**P01, P05, P08, P13, P14, P16**  
Координатор: **P13**.

Так как все участники группы указали доступность до 3 часов в неделю, берите короткие, чётко ограниченные сессии. Для технических вопросов назначается сменный контакт из групп разработчиков B/C.

## Этапы работы

### 1. Рубрика достоверности

Совместно определить:

- что является достаточным доказательством для величины;
- какие локаторы нужны для текста, таблицы, рисунка и скана;
- как фиксировать пропущенную единицу, неоднозначность осей, неверное сопоставление ряда и ошибки OCR;
- в каких случаях кандидат нужно отклонить, а не исправлять.

**Результат:** короткий документ/issue с примерами `approved`, `rejected` и `needs clarification`.

### 2. Калибровочные примеры

Выбрать небольшое число разрешённых источников или разрешённых фрагментов. Для каждого вручную зафиксировать правильные значения и доказательство: страница, таблица/рисунок/абзац и локатор области.

**Результат:** обезличенный набор эталонных `EvidenceRecord`, не содержащий исходные защищённые файлы.

### 3. Проверка харнесса

Запустить текущую версию харнесса на разрешённом материале и проверить кандидаты:

1. сравнить значение, единицу и контекст с первоисточником;
2. принять, отклонить или исправить кандидата;
3. написать краткую причину решения;
4. при ошибке оформить issue: вход, наблюдаемое поведение, ожидаемое поведение, источник ошибки (OCR, таблица, график, нормализация или orchestration).

**Результат:** review records и воспроизводимые issues/PR-предложения для разработчиков.

### 4. Цикл исправления

После PR от разработчиков повторить проверку на том же fixture. Закрывать issue только если исправление устраняет проблему и не ломает provenance.

**Результат:** подтверждение проверки в PR или новое уточняющее замечание.

### 5. Вклад в Hugging Face dataset

Публикуются только результаты, прошедшие экспертное ревью и обезличивание. Каждый эксперт создаёт PR в `top-papers/physics-agent-calibrations` **из своей учётной записи**, используя **свой персональный токен** локально.

Перед отправкой проверить:

- нет имён, e-mail/Telegram, токенов, путей к личным файлам и иных персональных данных;
- нет полных PDF/книг и иных материалов, которые нельзя перераспространять;
- сохранены `document_id`, номер страницы, modality и locator, но идентификатор документа не раскрывает закрытый URL или секретный путь;
- у каждой записи есть понятное экспертное решение и, при необходимости, комментарий;
- приложено описание происхождения данных и ограничений.

**Никогда не вставляйте Hugging Face токен в код, Markdown, issue, PR, переписку или историю shell.** Настройте его локально через официальный Hugging Face CLI/переменную окружения и отзовите токен при подозрении на раскрытие.
